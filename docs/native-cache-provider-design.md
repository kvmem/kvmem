# KVMem 多后端共享存储与资源策略实施计划

日期：2026 年 11 月 6 日。状态：Radiance 首轮增量快照已完成 GPU、SSD、并发分支及普通 IQ3R 256K 验收，见[测试报告](benchmarks/radiance-shared-snapshots-20261106.md)。下文区分当前接入与后续公共接口方向；阶段表保留完整路线，不表示全部扩展已经实现或验证。

采用公共存储与资源策略方案：KVMem 基于现有 `HostKvStorage`、`HostKvRecord`、`HostKvSource`、`SpillFile` 和 `StorageIoQueue`，统一 RAM/SSD 数据所有权、不可变共享、容量预留、I/O 及保留策略；Radiance、NInfer、PolyStrata 保留各自的 GPU 页管理、调度、原生格式和模型状态适配。Radiance 的增量 checkpoint 是首个落地用例，随后迁移 NInfer、PolyStrata。

公共策略控制数据放置与迁移需求，后端负责在安全边界执行 GPU 操作。GPU 页可直接安全复用时允许原生快速路径，不强制绕经 CPU。首次交付不接管 Radiance 的整套 `PrefixCache/IdleTiers`，不以改造它们作为先决条件。

多后端统一的是代码、策略、契约和观测口径。不同进程各有自己的账户和缓存域；同进程可显式配置共享父预算，但不同模型/后端的原生字节不能因共用存储实现而互相命中。公共层不引入 GPU 分配器，不统一 KV 字节编码，也不承诺跨进程或重启持久化。

## 首轮实现映射

公共存储继续使用 `HostKvStorage/HostKvRecord/StorageIoQueue`；新增 `SealedKvBlock/KvSnapshot` 表达不可变来源与执行视图跨度清单。原生页号不作为封存身份，跨分支继承强引用，查找表仅保存弱引用；对象生命周期与弱引用控制块防止地址重用误命中，不新增全局裸指针索引。

Radiance 的 `prefix_capture/refresh_captured` 提供布局与来源证明，`PrefixLease` 只捕获缺少的完整块和私有尾块，并复用已有归档记录。Query rewind 在发布截断时立即丢弃受影响来源。现有 `MemorySession`、异步停车事务和公共目录策略继续负责工作集、完成发布与取消，不为草案操作名称另建重复调度器。

当前恢复仍为所选执行窗口准备连续 staging，公共记录的冷读取不要求回驻 RAM；能力报告明确为 `full_selected_view`。更细的原生分批恢复、I/O 优先级和独立元数据额度仍需后续适配。新增快照清单按对象及容器容量计入已有逻辑留存准入，共享清单与来源只扣一次；分配器与控制块开销仍属于进程开销。

记录容量独立设置为 `--kvmem-cache-records`，默认跟随内容组上限，删除隐藏的 `max(16,N)`。比较共享与留存策略时显式设为 16 或 1，避免混淆归因。NInfer/PolyStrata 沿用既有接口，后续迁移到相同快照清单。

本轮验证单 GPU DFlash7；双请求测试证明功能并发及分支恢复，没有建立公平性或尾延迟性能结论。多 GPU/TP 运行验收、其他 draft 模式的本轮性能基线及更细的传输阶段计时仍待补充，不能从当前通过结果外推。

## 现有基础与需要修复的边界

- [memory_contract.hpp](../kvmem/include/kvmem/memory_contract.hpp) 已有 `BlockDescriptor`、`MemoryStamp`、`ExecutionView`、`MemoryTransfer`；区分逻辑位置、紧凑执行地址与原生物理页。保留这些概念。
- [kv_content.hpp](../kvmem/include/kvmem/kv_content.hpp) 提供逻辑前缀证明；该证明不能代替物理 KV 和模型状态证明。
- [content_cache.hpp](../kvmem/include/kvmem/content_cache.hpp)、[prefix_checkpoint.hpp](../kvmem/include/kvmem/prefix_checkpoint.hpp) 已有候选排序、目录、恢复点用途和留点规则。扩展现有语义，不另建一套同义策略。
- Radiance 的 `NativeMemory` 已维护逻辑块到原生页的映射，`TieredArchive` 已共享封存的历史归档。问题集中在 `PrefixLease` 新捕获执行视图时，`demote()` 全量复制原生页，再由 `TieredBuffer` 创建独立存储；已有快照的 `fork()` 能共享，不代表新捕获的快照能增量共享。
- 当前 Radiance 1.17 原生 `PrefixCache::lookup/insert` 与 `KVManager::adopt` 假定连续前缀及相符的块数量。KVMem 的逻辑进度可能是 256K，执行视图只有约 36K。仅修改哈希或命中条件不足以接入。
- 仓库 NInfer 补丁已有 checkpoint immutable origin、源保留分支及归档分配身份检查；PolyStrata 补丁已有 `park/fork/enter` 和原生 checkpoint。后续复用这些入口，不能据此假定两个后端已经具备 Radiance 式页池或相同的并发模型。

Radiance 的新旧 worker 对照已证明同模型、同原生处理行数下存在 prefill 回退；整份捕获在老版已存在。重复捕获、源保留时长和历史版本数量是分别需要测量的因素，不能将全部降速归因于某个未经计时的操作。

## 职责与单一所有权

| 工作 | 公共 KVMem | 后端及适配器 |
| --- | --- | --- |
| 选择与 Query 规则 | 预算选择、候选资格、continuation 门、恢复边界 | 提供真实 token、媒体、位置和状态证明 |
| 调度与 batch | 提交工作需求及等待状态 | 决定调度、批处理、设备安全边界 |
| 执行视图 | 原始位置、紧凑地址、逻辑进度 | 原生页表、张量和状态槽 |
| 恢复点目录 | 权威内容目录、候选排序、用途与限额 | 提供精确原生证明；迁移桥使用同一公共策略 |
| KV 存储 | RAM/SSD 对象、封存、共享引用、放置和释放 | GPU 原生页及其引用；捕获和恢复时提供格式映射 |
| 状态快照 | 用途、兼容域、提交条件 | recurrent、conv、MTP、DFlash、媒体位置等原生内容 |
| 物理资源账本 | 统一准入、RAM/SSD 账本、状态与临时资源子账户 | 执行原生 GPU 分配限制，报告真实占用及完成事件 |

每个缓存域只保留一个权威目录和一套资源策略。公共 `content_cache` 与 checkpoint 目录逐步承担目录职责；迁移期原生目录可通过桥接调用公共策略，但不得同时发布第二份可独立淘汰的目录和 KV 数据。未启用 KVMem 的原生模式继续使用后端自己的缓存。

已使用公共存储的路径直接复用；不为接口名称再加一层同义的字节容器。已有后端独立 RAM arena/状态池若暂时不能迁移，必须是明确受公共准入限制的过渡子账户，并报告实际复制与占用。它不能作为长期绕开公共放置策略的第二套缓存。

公共层第一阶段沿用现有正确的驱逐机制，先补足共享、记账和非阻塞接入。预取、读写优先级、I/O 合并及更细的冷热策略通过统一扩展点逐步增加，避免同时改变所有策略而无法归因。

## 公共数据模型

### 缓存域

新增 `CacheDomain` 概念，以后端运行实例和兼容配置为边界。验证至少包括模型权重身份、适配器/LoRA、KV 编码和 scale 布局、状态 schema、位置编码配置、rank 分片布局及会影响有效执行状态的配置。可包装现有 `BackendIdentity` 与 `PayloadLayout`，不把后端裸指针当作长期身份。

不同加载实例即使模型名称相同，也不能直接交换原生句柄。客户端会话 key 不是恢复证明，也不能替代服务部署所需的缓存隔离域。

### 不可变数据引用

使用 `PayloadLease` 表达对封存数据对象或经验证对象范围的引用；实现优先组合现有 `HostKvRecord::fork()` 和 `HostKvSource`，不另造字节分配器。公共层拥有 RAM/SSD 对象，适配层解释布局；可选 `NativeViewLease` 只保留原生 GPU 页，必须带后端安全释放机制，不作为可直接写 SSD 的对象。

`PayloadId` 是域内不可复用的存储身份，必须有防止对象销毁后身份重用的 generation。它不等于逻辑 block ID、内容组、token 哈希或 GPU 页号。租约保留内容，不要求内容一直驻留在 RAM 或 GPU。

已有封存块的派生分支继承引用；新计算或无法证明相同的版本创建新引用。尾块增长、重放和分支变更不得仅因版本数字相同而合并。前缀摘要用于筛候选，不用来直接认定两份原生 KV 字节相同。

KVMem 逻辑块可能覆盖多个原生页、多个层/scale 平面。适配器使用描述符数组和原生布局处理映射；公共层不要求逻辑 block size 等于原生页大小。不支持部分范围复用时复制对应完整原生单元，并如实报告能力。逻辑上按块引用，物理上允许批量分配/读取和聚合传输；不要求每块各发一次 I/O 或 DMA。

### 恢复点与历史记录

一个 `RecoveryPoint` 是一个不可变、可独立验证的恢复包，包含：

- `CheckpointId`、用途集合和 accepted frontier；仅纳入已接受的推测结果。
- 精确输入身份及媒体/位置证明的句柄。
- `ExecutionView`：所选逻辑块、顺序、版本、紧凑地址和可见 token 数。
- 对该视图所需 KV 的不透明租约。
- 原生状态租约：循环状态、draft 窗口、必要的模型状态；各自位置须与恢复边界一致。
- KVMem 基线：逻辑历史目录、冷历史归档引用、统计、选择器和反馈的相容版本。

只保留所选 36K 的 KV 不足以支持未来 Query 召回，因此完整的可召回历史目录与冷数据引用必须随恢复包保持一致。活跃历史、冷归档与 checkpoint 引用同一物理对象时只计一份。

模型状态和策略状态可以保持后端私有类型，但必须能封存和在恢复时创建独立可变分支。`shared_ptr<const T>` 本身不能阻止隐藏的可变别名写入。

原先一条记录的主恢复点、input 和 fallback 可表现为一个元数据集合引用多个 `RecoveryPoint`。数量指标分别报告记录、恢复点和独立物理数据；不把容器层次固定成所有后端都必须遵循的 ABI。Query replay 临时恢复点属于活动事务，不自动成为长期目录项。

## 公共接口草案

在现有 `MemoryBackend/MemoryTransfer` 旁增加公共恢复点协调器与可选的 `NativeCheckpointAdapter`。前者管理目录、事务、共享存储和资源策略；后者只提供原生校验、捕获、恢复与设备生命周期，不自行决定跨请求留存和 RAM/SSD 驱逐。保留现有工作集接口，不增加纯虚方法强迫所有后端同时重写。下列名称是语义草案，具体 C++ 签名在最小适配验证后固定。

| 操作 | 所属层 | 契约 |
| --- | --- | --- |
| `lookup(query)` | 公共协调器 | 返回候选与稳定源引用；候选不代表恢复成功 |
| `capabilities/validate` | 原生适配器 | 返回域、布局与精确恢复证明；公共资格门也必须通过 |
| `describe_capture(expected, view)` | 原生适配器 | 返回稳定来源、原生映射、已有封存引用及缺少的数据；不得猜测版本相同 |
| `prepare_capture/prepare_restore` | 公共协调器 | 预留所有必要资源并创建事务；源不变，目标独占 |
| `capture_missing/restore_view` | 原生适配器 | 在设备安全边界只搬运所需范围，报告完成事件和实际字节 |
| `commit_restore` | 原生适配器与协调器 | 全部就绪后一起提交视图、进度、原生状态和 KVMem 基线 |
| `publish/retire` | 公共目录 | 原子发布完整恢复点；淘汰只释放目录引用 |
| `place/prefetch/trim` | 公共资源策略 | 按额度生成迁移计划，GPU 部分由后端接受或明确拒绝 |
| `usage()` | 公共账本和原生适配器 | 汇总实际物理占用、预留及在途资源，去除重复计费 |

公共资源策略接收用途、冷热、下一次使用需求、已有副本和成本提示，输出有预算依据的放置/迁移计划。先定义接口和确定性默认策略；未来可替换 RAM 淘汰、SSD 写出优先级和预取规则。持有裸字节的公共存储不能自行判断模型恢复资格。

捕获事务提供 `advance/poll/take_ready/cancel`；恢复事务提供 `advance/poll/commit/abort`。`commit` 必须在引擎安全边界，成功同时提交逻辑进度、执行绑定、原生状态及 KVMem 基线。目标恢复失败可返回“旧目标完整保留”或“目标已失效”；不能宣称 GPU 写入总能回滚。源快照在两种情况下均不受影响。

异步 CPU/I/O worker 不调用 GPU 或修改目录；其完成通知交还引擎。需要设备搬运时，通过后端调度步骤启动和确认完成。能力位区分“有非阻塞等待协议”和“可以与计算重叠”，不能用同步包装伪称异步。

能力至少区分：稀疏视图恢复、不可变 fork、跨新捕获的增量复用、原生页引用、尾块 COW、状态/窗口恢复、异步读写、分层存储、TP 原子恢复及物理记账。普通运行时动态条件仍逐次验证，能力位不代替证明。

## 命中与执行状态校验

命中流程为：限定兼容域 → 内容候选 → 公共 Query/continuation 资格门 → 后端精确证明 → 预算预留 → 私有目标恢复 → 提交后报告实际命中。

保持现有规则：新用户 Query 可发现兼容前缀；工具续接只恢复已证明的 continuation，随后 append 与 resident-only Pressure。载入恢复点所需的冷数据，不代表允许使用旧 Query 重新选择冷历史。

不以 `MemoryStamp` 的整结构相等代替跨会话证明：分支的 `SessionIdentity` 本来就不同。源内使用 stamp 检查异步任务是否过期；跨分支使用不可变来源、内容证明、执行历史及状态完整性验证。当前 `execution_history` 计数也不能作为跨会话全局身份。

当前选择集不同不必立即否定所有历史块复用：旧块若确实继承同一封存对象仍可共享。但在不同稀疏上下文下新计算的 KV，不能因 token 相同而混为同一个原生版本。

无 logits 的恢复点按现有规则留出重新计算 logits 的 token。任何重放区间由显式计划给出；不能在切换到原生缓存后静默恢复旧的 draft refill 提前量。

## 捕获与恢复流程

捕获只在 producer 完成、accepted frontier 固定后开始。先取得稳定源和预算，生成 manifest，复用已封存对象；只为新块和变化块准备 DMA 与存储。完整成功后封存为恢复点，再原子发布目录。失败丢弃私有目标，保留原执行状态和旧恢复点。

恢复先持有源并创建独占目标分支，准备预算，分批读取冷对象。若后端支持对该布局直接采用 GPU 页，可增加原生引用；否则载入新页。恢复视图、原生状态与 KVMem 基线全部就绪后才提交。多个请求可以读同一源，但不能获得同一可变执行绑定。

事务状态必须有明确的 `Prepared → InFlight → Ready → Committed` 和取消/失败支路。取消请求不是资源已释放的证明；运行中的 DMA 或 I/O 排空前，缓冲区、页引用和预算继续存活。设备销毁在合适的 rank/stream 安全边界执行。

所有源在规划到提交之间都持有租约。目录锁只保护元数据，不进行 I/O、GPU 等待、原生验证或最后一个设备对象的析构。固定锁顺序与取消回调归属，避免引擎锁和存储锁互相等待。

元数据清单允许持久化结构共享或分段数组，避免每次追加为全部历史块复制一套大型目录；这与 KV payload 复用分开计量。

## 资源预算与保留策略

一份物理数据只有一个权威账户。RAM/SSD payload 使用公共存储账户；原生状态和设备临时资源接入公共预留及释放回执，不能只在事后报告。不能在原生 H 和公共 H 各扣一次，也不能分别各允许完整 H。共享引用不新增 payload charge；将 GPU 对象保存为新的 host 对象仍需为新副本计费。

分别记录 GPU KV、RAM payload、SSD payload、原生状态、元数据、pinned/staging、在途预留与读者保留的物理字节。GPU 模型权重/工作区和进程 RSS 另外报告。迁移时同时存在两份物理副本就同时计费；队列同时限制任务数和持有字节。恢复规划保留一次可完成的换入/换出余量，不能把预算全部许诺给静态历史。

查找索引不能无界强持有数据；存活引用由活动视图、归档、恢复点和在途任务负责。磁盘读取不要求整份恢复点回驻 RAM，按后端支持的有界单元搬运。没有此能力的适配器必须报告其实际 staging 上限。独立状态预算不偷偷并入已有 H 参数；配置版本、有效预算和进程总开销分别展示。

并发请求共享存储账户和有界 I/O 队列。公共策略为恢复、强制换页、可选快照和预取区分用途，并保留公平性；可选任务不能耗尽继续执行所必需的额度。后端只提交需求并接收 Pending/拒绝，不在引擎锁内等待公共存储腾出容量。显存预算由公共准入与后端真实几何共同校验，不把 token 数直接当作通用字节数。

容量配置分开表达：内容组上限、已发布历史记录上限、保留恢复点上限、元数据字节上限和在途预算。提供版本化的有效配置报告；不静默改变既有 `cache_sessions` 的含义，也不保留 `max(16,N)` 这种隐藏记录上限。具体默认值在资源对照后确定，性能报告必须列出有效值。

淘汰分为两类：无损覆盖压缩须证明旧恢复能力完整保留，包括模型状态、策略基线和冷历史；普通容量淘汰允许降低后续命中率，但必须保护已经取得的租约。同组、较新 frontier 或 KV 超集本身都不足以证明旧 checkpoint 可无损删除。

## Radiance 接入方案

保留原生 Scheduler、KVManager 和 batch 执行；KVMem 模式继续关闭原生 PrefixCache 的独立历史保留与 tiering 路径。利用现有原生页 API、`NativeMemory`、`RankNativeMemory` 和公共存储修复快照，不改写连续前缀 `insert/adopt` 的语义。

`NativeMemory` 输出经过 accepted 边界验证的捕获描述，包括逻辑 frontier、visible tokens、块版本、原始位置/原生页映射和已有归档引用。新增捕获成功后将不可变来源关联到后续的 append、fork、rebind 和 rewind 生命周期，不能只复用已落盘冷块而让一直驻留的热块每轮重新捕获。

将 `PrefixLease` 的全量连续 KV blob 改为执行视图清单与公共封存记录引用。能直接使用 `TieredArchive` 的同版数据就复用；布局不同则提供显式跨度映射或有预算的转换。首版尾块、循环状态和 DFlash 窗口保守独立保存，复用现有安全路径；完整未变块不再整份 D2H 和重新 allocate。

恢复按清单分批读取到有界缓冲区，复用原生稀疏表发布能力，最后统一提交状态。热路径只在原生证明和显存预算允许时直接引用 GPU 页；长期目录不能为图方便钉住另一整套执行视图。`StateCheckpoint/WindowCheckpoint` 的字节、staging 和完成事件纳入公共资源报告及准入。

Radiance 原生 tiers 的进一步复用从首轮交付中移除。将来若某个低层传输原语有明确收益，可以接入公共策略执行端；不能因此另起原生的独立目录、RAM 额度或 SSD 策略。完整注意力原生模式与 KVMem 模式保持兼容域隔离。

## NInfer 与 PolyStrata 接入方案

| 后端 | 已有接入基础 | 首轮迁移 | 后续优化 |
| --- | --- | --- | --- |
| Radiance | `NativeMemory`、原生页表、公共归档、状态与窗口保存 | 公共块引用与增量捕获，统一生命周期与预算 | GPU 页快速路径、有界批量搬运 |
| NInfer | `KvmemPrefixCheckpoint`、immutable origin、封存历史、归档共享、原生 lane I/O 边界 | 接入公共协调器、资源策略和指标，复用现有公共存储 | 消除剩余状态/归档重复复制，保留 lane 异步调度 |
| PolyStrata | `KvmemHistory`、`KvmemCheckpoint`、`KvmemParked`、`park/fork/enter` | 将 parked/fork 对接公共恢复包与统一存储准入 | 批量搬运、状态封存和可支持的非阻塞路径 |

NInfer/PolyStrata 的上述基础来自本仓库补丁，不代表本次完成了上游完整源码和 GPU 路径验收。迁移前记录各自锁定版本、补丁组合与实际能力。公共接口不要求后端具备同样的 GPU 共享、TP 或并发数量；不具备的能力保持明确的兼容实现。

保留其他后端现有 `MemoryBackend` 工作集切换路径。迁移逐个后端进行，新旧实现启动时选择，同一缓存域不能双写两套实现。运行中的目录不能直接从旧格式切到新格式。回退应排空任务和旧目录，不尝试将新句柄交给旧 worker。

## 实施顺序与交付边界

| 阶段 | 工作与交付物 | 完成条件 |
| --- | --- | --- |
| 0 基线与归因 | 固定 worker/模型/GPU/配额；增加 capture、共享、D2H、队列和存储等待指标 | 同输入同模型复现，能区分处理行数、复制量与等待 |
| 1 公共契约 | 恢复点协调器、原生适配器协议、稳定封存身份、资源类别与有效配置；主机模拟适配器 | 生命周期、预算、源保护、取消及过期回调主机测试通过 |
| 2 公共存储接线 | 复用 HostKvStorage/Source/Record/IoQueue；接通目录和物理账本；形成公共放置策略入口 | 不双重存储/计费，异步读写不阻塞引擎锁，在途内存有界 |
| 3 Radiance 增量快照 | NativeMemory 描述与版本沿袭；PrefixLease 块清单；批量捕获/恢复 | 两个不同 frontier 的未变完整块身份相同，无重复 D2H/分配，KV/scale/状态字节正确 |
| 4 完整功能与留存 | input/fallback/endpoint、Query replay、draft、取消、多并发、TP；留存限额单独提交 | 所有声明能力通过，实际记录/恢复点/物理数据数量分别可观测 |
| 5 Radiance 性能交付 | 14 轮定位对照、33 轮 256K、并发公平性与尾延迟；审计修复再审计 | 相同预算下消除可复现回退，恢复正确、无泄漏或隐藏预算增长 |
| 6 NInfer 迁移 | 包装现有正确恢复路径，接入相同存储/资源策略与公共测试 | 后端原生状态测试与自身基线通过 |
| 7 PolyStrata 迁移 | 对接 park/fork/enter，统一目录准入、取消和记账 | 后端原生状态测试与自身基线通过 |
| 8 分层策略优化 | 基于统一指标逐项加入预取、I/O 合并、优先级和更细冷热策略 | 每项独立对照有收益且资源/公平性不回退 |

首轮实现范围为阶段 0—5。公共接口为阶段 6—7 保留能力，但不在 Radiance 修复中顺带重写另两个后端。阶段 8 是后续优化，不作为本次修复的完成条件。

公共协议、存储接线、Radiance 接入和留存策略分别提交；新路径通过字节/状态与资源验收后才成为默认。审计发现问题先修复再复审，形成各阶段证据后提交合并。回退通过启动时选择旧实现完成，不在线转换存量对象。

预计修改入口：公共 `memory_contract` 的兼容扩展及新增恢复点协调器、现有 `content_cache/prefix_checkpoint`、`host_kv_storage/storage_io_queue` 的必要扩展；Radiance 的 `native_memory/rank_native_memory/prefix_lease/rank_prefix/statistics_observer/batched_observer`。实际文件拆分以最小职责为准，不预先引入全套新的同义类型。更新公共内存契约、配置文档及指标说明；不修改选块算法来掩盖性能回退。

## 验收与性能归因

| 场景 | 核心断言 |
| --- | --- |
| 按完整块连续追加 | 已封存未变块保持同一物理身份，不因新增 checkpoint 再次 D2H/分配；新增字节对应变化部分和状态 |
| 部分尾块追加、尾页跨界 | 旧恢复点逐字节不变，新尾块独立；无效 padding/scale 处理符合原生格式 |
| 同 token 不同执行历史 | 错误复用被拒绝，不能靠 token hash 合并状态 |
| 非连续选择、Query 重放、工具续接 | 原始位置、frontier、KV、统计及状态一致；续接不越权触发冷重选 |
| A/B 并发恢复、B 编辑或取消、目录淘汰 A | 源与其他分支保持可恢复，最后引用释放后回收物理资源 |
| GPU 页号复用、版本回绕保护、过期任务 | 不得误命中或把旧完成回调发布到新会话 |
| 队列满、RAM/SSD 满、部分写失败、DMA 失败 | 源保留；目标失败语义明确；资源和预留最终回收 |
| DFlash/MTP、媒体边界、TP 某 rank 失败 | 完整原生状态证明；未验证的组合拒绝能力，不发布半套恢复点 |
| 原生常规前缀缓存 | 无 KVMem 时行为与资源保持正常，KVMem 模式不双重启用缓存所有者 |
| 多请求争抢共享预算 | 恢复/强制换页可继续推进，可选写出/预取不导致死锁或长期饥饿 |

增加每请求指标：捕获复用/新建字节、实际 D2H/H2D、存储实际写入/读取字节、目录记录及恢复点数、唯一数据量、GPU/RAM/SSD/state/staging 峰值、共享来源及拒绝原因。时间拆分 producer drain、capture、排队、存储、restore 与调度等待；并行区间不能直接相加当作总耗时。

分别报告 planned/actual cached tokens、实际模型处理行数和实际恢复位置。原生 prompt 时间包含等待，不把它称为纯 GPU kernel prefill 时间。

性能臂包含：原基线、仅公共存储增量快照、仅留存策略变化、两者合并。固定同模型、GPU、输入、预算、输出/思考上限、draft 配置、预热与冷/暖状态；基线有限次重复用于建立波动区间。先跑既有 14 轮定位用例，再跑 33 轮 256K 任务，最后验证多并发吞吐、公平性和尾延迟。受控基准的输出/思考限额不修改用户聊天服务的无限制默认设置。

结构验收要求共享比例和实际新增数据符合预期，不能仅看 tok/s；运行验收要求恢复正确、无容量外溢/泄漏、取消收敛，并在相同预算下消除可复现的性能回退。数值阈值以固定基线及其波动确定，不预先承诺理论线性加速。模型任务质量另行检查，缓存字节正确不等于最终任务答案正确。

## 待最小验证确定的实现选择

- 已驻留热块的封存引用如何随原生 append/fork/rebind/rewind 延续和失效，避免首次捕获后仍重复保存。
- 归档数据与原生恢复页是否可直接共享同一对象；若布局不同，转换成本、缓存寿命与计费必须明确。
- 共享记录和原生传输的聚合粒度、元数据清单结构共享，以及状态/staging 的预留范围。
- NInfer/PolyStrata 已有公共存储接入范围、独立原生池的迁移成本和能力矩阵。

这些选择不改变公共语义：源不可变、恢复包完整、逻辑位置与物理页分离、物理数据只有一个权威所有者、失败不破坏已发布源。
