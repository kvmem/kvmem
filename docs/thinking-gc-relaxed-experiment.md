# Thinking 主动回收：双指标实验版

2026-11-12。应本轮要求，增加可选的宽松内容判断，严格策略仍为默认。

## 实现范围

NInfer 原生服务同时使用 `--kvmem-gc-step-redundancy --kvmem-gc-step-relaxed` 开启实验版。
`/props` 的 `kvmem_gc.step_content_rule` 应为 `attention_redundancy`，`step_similarity` 为 `0.85`。
只开 `--kvmem-gc-step-relaxed` 会报参数错误，避免误以为已启用主动回收。

在已经标出的完成步骤中，对 thinking 源页寻找一个后续保留页：

1. **Attention 重要性：** 源页被实际采样的输出 attention 重要性不高于保留页。
2. **Redundancy：** 两页 Mean-K 描述向量的余弦相似度至少为 0.85。

实验版不要求源页的数字及附近文字在保留页中逐字重现；不增加冷却次数、绝对重要性上限或额外 LLM 复核。严格版的相似度门槛仍为 0.90，保留原字面检查。

重要性取每个问题周期内已采样的输出 attention 峰值。原严格策略取 Query 检索分数与该 attention 峰值的最大值。实验版改用 attention 本身，所以两种策略的通过集合并不保证包含关系；它不是只把一个数值门槛调低。未观测 attention 不能当成已观测到零，后续第一次实际观测会让相关候选重新尝试。

此次复用现有的非 thinking 输出采样（`accepted_output_samples`），并非新增全 token、全层的 attention 计算。因此在当前回复仍处于 thinking 时，新问题周期内的候选可能显示 `pending_features`，等非 thinking 输出出现后再评分。这是注意力数据的现有采集范围，不能把没有观测解释为内容不重要。

范围仍是已完成的 thinking 与其后续保留内容。64-token 完整页、来源与句柄身份、前台正在使用的引用、MTP 一致性及安全提交边界属于实际存储约束，继续保留。后续见证页仍需保留。缺少 attention 观测的页面不盲删；容量 LRU 仍是独立策略。

本次不改变增量换窗、检查点恢复和自然交接流程。标记排除与 Host 实际释放分别计数，不能把候选数量当成已释放数量。

## 本地验证

`historical_gc_step_redundancy_test` 新增以下场景，并保留原生命周期测试：

- Query 分数存在但没有输出 attention 时不产生删除批准；收到首次 attention 后重新评估。
- 高 attention 的源页保留；低 attention 的源页在余弦 0.86 时可通过，即使数字匹配掩码为空。
- 余弦 0.84 不通过；单测向特征接口显式写入零 attention，验证它与缺失观测的区别。当前原生采集只发布正值，零值及未驻留页仍可能显示为未观测。
- 正在被引用的源页不会提交删除，过期 Query 的批准不能提交。

同时运行 `historical_gc_ninfer_core_test`；原生 `ninfer_serve_options_test` 验证默认严格、显式开启及错误组合。实际执行结果随验收证据记录。

## 真实模型初测口径

使用 R13 的 `llm-inference-batching-scheduler` 前 7 次真实 Agent 请求，严格版和实验版使用同一个新二进制，逐次输入内容一致，每组重启模型并重置 Host KV。

沿用 Qwen3.8-27B IQ3_S、RK4V4、MTP4、64 tokens/页、96K active、16K 生成预留、4,760 MiB Host、sink 2,048、recent 64。每次请求仍有 16K 总输出上限和 4K 思考上限，采样参数保留。两组都只发送 thinking 候选，移除重复工具反馈候选；容量 LRU 设置不变。

统计实际 thinking 标记与物理释放、候选筛选原因、服务错误、输出量、MTP 接受率、decode 轮间隔、搬运量和请求耗时。日志中的各类拒绝是顺序判断的次数，不能相加解释为独立被拒块数。

这是冻结请求回放：下一次请求使用原始记录中的 Agent 历史，不使用本次模型输出，不执行工具及官方 verifier。因此不提供 Terminal-Bench 官方 reward，也不能由这项测试断言完整任务质量或完成速度改善。

后端补丁序列新增 `ninfer-step-gc-relaxed.patch`，本次验收的原生源码树为 `50a5ec807afadfa18c74c8b8fb122221c3d3d216`。

## 本轮实测结果

两组共 14 次请求全部 HTTP 200，全部以 `stop` 正常结束，14 份输出均为包含 Terminus 必需字段的 JSON 对象。没有执行工具或官方 verifier，官方 reward 为未测，不能把这些请求计为 14 道通过的任务。

两组均提供两个 thinking 范围，共 90 个完整候选页：

- 严格版：标记 0 页、实际释放 0 页。
- 放宽版：标记 3 页、实际释放 3 页，均为 thinking，逻辑页号 99、101、110。按 64 tokens/页计为 192 tokens 对应的 Host 槽位，候选回收比例 3/90（3.33%）。这不等于进程 RSS 下降同等大小。
- 两组均未发生容量 LRU 释放；本轮没有混入重复工具反馈回收。
- 两组前五次输出逐字节一致。第六次输出为严格版 4,667、放宽版 6,156 tokens；第七次为 5,131、3,136 tokens。输出变化不自动意味着质量提高或退化。

原始计时与搬运观测（严格版 → 放宽版）：

- 七次请求耗时合计：576.50 → 645.18 秒。
- 原生 decode 轮间隔 p95：92.17 → 93.91 ms（MTP 轮次口径）。
- decode 吞吐：47.50 → 42.33 tokens/s；MTP 接受率：65.20% → 62.88%。
- Host→GPU 载荷：2,142,228,480 → 2,045,962,240 字节；GPU→Host：885,893,120 → 968,755,200 字节。

**本轮不能据此认定速度收益。** 在尚无 GC 候选的前两次请求中，两组输出和草稿/接受 token 计数相同，放宽版却已明显较慢。实测快照显示 GPU 温度 86℃、SM 时钟 735MHz、`SW Power Cap` 生效；该次状态快照的热降频标志并未生效，不能把功耗限制误写成已证实的热降频。

此外，冻结回放的第七次请求仍包含原记录中的第六次回答，而放宽版刚生成了不同的回答，导致前缀可复用长度为 30,107，低于严格版的 34,774；新增 prefill 为 9,064 对 4,397，相差 4,667 tokens。第六次请求本身两组仍命中相同的 28,968-token 前缀。因此不能把第七次的差异直接解释成“主动 GC 破坏全部前缀缓存”，它也包含固定历史回放与本次输出不一致的影响。搬运量同样受到输出长度和恢复范围变化影响。

结论是：双指标实验入口和实际释放路径已验证，放宽版比本轮严格版多回收 3 个 thinking 页；尚未证明完整任务质量或完成速度提升。正式质量结论需要完整 Agent 任务对照，性能结论需要稳定硬件状态并排除回放历史不一致。
