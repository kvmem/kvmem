# RX 7800M：DFlash2 复测与 GPU 功耗

2026-11-16 11:25–11:31（UTC+8），在同一台 RX 7800M 上按 **关闭→开启→开启→关闭** 顺序完成四轮复测。模型、推理二进制、预算和请求保持一致。三类长回答综合解码速度为 **13.80 → 25.32 token/s，提升 1.83 倍**；对应生成请求期间平均 GPU 功耗为 **82.1 → 117.6 W**。

功耗来自该卡驱动的 **AMD ADLX `GPUPower`**。此驱动明确报告不支持 `GPUTotalBoardPower`，所以这里不是整卡 TBP，也不是插座或整机功耗。AMD 将两项作为不同接口，并将包括显存等板上组件的功耗归入 `GPUTotalBoardPower`：[官方接口定义](https://raw.githubusercontent.com/GPUOpen-LibrariesAndSDKs/ADLX/v1.5/SDK/Include/IPerformanceMonitoring.h)。没有根据 TDP、利用率或功耗百分比估算瓦数。

## 主要结果

每种模式运行两轮；每轮包括哈希表解释、LRU 代码/解释、BFS 迷宫解释三个请求，每个请求最多输出 256 token。下面每种模式合计 6 个长回答、1536 个输出 token。

| 模式 | 综合解码速度 | 生成请求平均 GPU 功耗 | 生成请求采样峰值 | 请求 GPU 能耗/输出 token |
| --- | ---: | ---: | ---: | ---: |
| DFlash2 关闭 | 13.80 token/s | 82.1 W | 90 W | 6.09 J |
| DFlash2 开启，7 个草稿 token | 25.32 token/s | 117.6 W | 137 W | 5.10 J |

开启后速度提高约 **83%**，请求期间平均 GPU 功耗提高约 **43%**，完成相同输出 token 数的请求更快；在这一组任务中，每输出 token 的 GPU 能耗约降低 **16%**。这是传感器所覆盖的 GPU 能耗，不能推广为整卡或整机节电比例。

速度使用服务器报告的纯解码时间，排除预填充和第一个输出 token。功耗和能耗使用客户端实际请求起止区间，包含短提示预填充、生成以及返回前的处理。因此不能把表中的平均功耗直接乘以纯解码时间来复算请求能耗。功耗均值按时间加权梯形积分计算，能耗分母使用完整输出 token 数。

| 复测轮次 | 模式 | 综合解码速度 | 平均 GPU 功耗 | 采样峰值 |
| --- | --- | ---: | ---: | ---: |
| 1 | 关闭 | 13.85 token/s | 81.8 W | 84 W |
| 2 | 开启 | 25.15 token/s | 116.8 W | 131 W |
| 3 | 开启 | 25.49 token/s | 118.4 W | 137 W |
| 4 | 关闭 | 13.76 token/s | 82.4 W | 90 W |

| 任务，两轮合并 | 关闭速度 | 开启速度 | 关闭平均 GPU 功耗 | 开启平均 GPU 功耗 |
| --- | ---: | ---: | ---: | ---: |
| 哈希表解释 | 13.71 token/s | 24.84 token/s | 81.2 W | 118.3 W |
| LRU 代码/解释 | 13.90 token/s | 24.53 token/s | 82.4 W | 118.7 W |
| BFS 迷宫解释 | 13.80 token/s | 26.68 token/s | 82.6 W | 115.6 W |

与[前一轮结果](radiance-v2-dflash2-rx7800m-20261116.md)的约 1.80 倍加速一致。本次重新测得的数据独立记录，没有混用前一轮速度或选择最快一轮作为汇总值。

## 预填充、温度与采样边界

3985-token 文档请求的功耗单独统计，不混入上面的三个长回答：

| 模式 | 文档请求平均 GPU 功耗 | 文档请求采样峰值 |
| --- | ---: | ---: |
| 关闭 | 123.0 W | 151 W |
| 开启 | 115.4 W | 146 W |

文档请求以预填充为主，还包含简短 ACK 和返回处理，不能将这一区间视为完全排除了其他工作的预填充内核测量。整个复测过程最高采样值为 **151 W**，该值出现在文档处理期间。测试前空闲约 **4 W**、GPU 利用率 0%，温度 38°C。

长回答期间最高 GPU 温度两种模式均为 **54°C**；热点最高为关闭 **62°C**、开启 **69°C**。整个请求集包括文档时，最高 GPU 温度为 **56°C**，热点最高 **75°C**。没有修改电源限制、频率、风扇策略或驱动配置，也没有据此判断是否触及温度或功率限制。

采样器独立于推理控制进程运行，每 250 ms 请求一次 ADLX 实时读数。共 **1419 个有效样本、0 个错误**，相邻采样间隔中位数 250 ms、最大 266 ms，单次查询最长 32 ms。保留了驱动时间戳、主机单调时间、UTC 时间、温度、热点、核心/显存频率、利用率和显存读数。功耗归属依 PCI 地址 **0000:0c:00.0** 与 HIP UUID 核对，记录的是外接 RX 7800M，不是机器内的 RTX 3080 Ti。

所有均值使用同一主机的单调时钟与请求区间对齐；峰值是采样到的最大值。传感器刷新和 250 ms 轮询会漏掉更短的尖峰。读数是整颗 GPU 的活动，包含该 GPU 上其他进程可能产生的负载；开始时未发现其他 Radiance 测试服务，空闲采样为 0% 利用率。这仍是两组短时对照，不是持续满载、稳态散热或宽泛能效评测。

## 配置与验证

- 模型：`qwen3.8-27b-iq2r-l-v4.rad`，复用通过国内镜像下载并校验的文件；SHA256 `89fb6bfbd602594ed8a79b655bee7e15e7732b7c2c78e34db3d145b2e58706bd`。
- Windows RX 7800M/gfx1101，12 GiB；显示驱动版本 `32.0.32015.7029`。
- Radiance 2.0，`libr3diqr 0.3.0-dflash2`；本轮没有重新编译或修改推理代码。工作程序、核心及两个内核 DLL 的哈希与前一轮最终验证版本一致。
- TP1/C1，逻辑上下文 8192，prefill 256，budget 3072，sink 128/recent 2176，BF16 KV，F32 循环状态，Query 256/replay 512，主机历史 2048 MiB。关闭模式同样使用 budget 3072，保证对照一致。
- 使用正式 `rx7800m-iq2r` profile 环境：`OMP_NUM_THREADS=2`、`KVMEM_CAPTURE_EARLY_SEAL=1`。请求温度为 0，提示和输出长度相同。
- 四轮均通过算术、110-token 整数序列、三个长回答、超预算文档及跨轮召回、末尾恢复请求。召回正确回答 `68391`，复用 3986 token，monitor 显示选择 3072 token；开启模式确认有实际草稿提出和接受。
- 总计 32 个请求。生成类回答开关前后不保证逐字一致，256-token 代码回答也未作为完整程序执行；本次没有新增质量等价性结论。
