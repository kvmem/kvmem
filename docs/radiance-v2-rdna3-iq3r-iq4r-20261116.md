# RDNA3：Qwen3.8 IQ3R / IQ4R-S 修复与验证

本次针对已提供的 Qwen3.8-27B IQR v4 模型目录逐项检查量化编码，并使用 Windows
RX 7800M（gfx1101，12 GiB 显存）进行短文本验证。结果不代表所有 IQ3R/IQ4R
模型、所有 RDNA3 显卡、Linux 或图像路径均已验证。

## 修复

- Linux 下允许构建并注册 gfx1100–gfx1103 的 `libr3diqr`，缺少 `rope_table` 时
  Qwen 回落到普通 norm + rope 路径。
- IQ3R：支持 1024 行 Trellis 分组及 u3 词嵌入；该文件有 120 个 u4、1024 行分组
  的权重。IQ4R-S 使用 u4 词嵌入和 48 个 u5/BF16 分组标度权重。
- 为 u5/BF16 分组标度补全解码、窄矩阵、分块预填充及门控路径的逐行标度计算。
- 修正 `layer_offload` 时模型权重预算向上取整可能使 KV 池减少 1 MiB、导致启动失败
  的问题。界面提供模型权重主存预算与卸载模板，和 KV 主存预算分开设置。

## 验证

在 Windows 11、RX 7800M、BF16 KV、单卡单会话条件下，两个模型的算术和序列生成
请求均通过；DFlash2 测试各生成 14 个草稿 token，其中 8 个被接受。速度是短请求
中的记录，受 prompt、预算、设备链路和缓存配置影响，不能当作长期基准。

| 模型与模式 | 解码 token/s | 输出 token | 权重放置 |
| --- | ---: | ---: | --- |
| IQ3R，草稿关闭 | 13.28 | 30 | 显存 10.40 GiB，主存 464 MiB |
| IQ4R-S，草稿关闭 | 0.23 | 30 | 显存 7.39 GiB，主存 5.56 GiB |
| IQ3R，DFlash2 | 1.12 | 11 | 显存 7.07 GiB，主存 5.38 GiB |
| IQ4R-S，DFlash2 | 0.79 | 11 | 显存 6.75 GiB，主存 7.80 GiB |

普通解码的峰值显存采样分别约为 11.41 GiB 和 11.73 GiB。IQ4R-S 的主存卸载
需要频繁通过外接链路传输权重；DFlash2 为两个模型额外占用了显存和主存。
测试使用 8 GiB 的权重主存池，主存中的实际权重总量见表格；两个模型的预填充、
KV 和选择预算并不完全相同。

GPU 数值测试通过 222 项检查，包含 u5/BF16、1024 行分组和 2/3/4 位词嵌入；
DFlash2 专项测试通过。Linux 主机侧插件注册编译通过，Qwen 无 `rope_table` 回退
及层卸载 KV 预算边界测试通过。修复版 GPU 插件包含 gfx1100 和 gfx1101 代码对象；
RX 7900 XTX（gfx1100）与 Linux ROCm 的模型运行仍需在该机器上确认。
