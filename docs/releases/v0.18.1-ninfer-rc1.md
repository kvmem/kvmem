# KVMem v0.18.1 NInfer RC1 · Windows RTX 20 / V100

发布日期：2026-10-15。

这是面向 RTX 20 系、TITAN RTX 和 Tesla V100 的首轮实机验证包。两个 Windows x64 ZIP 只包含 NInfer 后端、启动脚本和运行依赖，模型需要另行准备。源码固定到 `iamwavecut/ninfer-all` 的 `1383a50e4153`，并应用 KVMem 集成补丁。

## 下载选择

| 显卡 | CUDA 架构 | 构建 Toolkit | ZIP |
|---|---:|---:|---|
| RTX 20 系 / TITAN RTX | sm75 | CUDA 13.2 | `kvmem-v0.18.1-ninfer-rc1-windows-rtx20-sm75.zip` |
| Tesla V100 | sm70 | CUDA 12.9 | `kvmem-v0.18.1-ninfer-rc1-windows-v100-sm70.zip` |

两个包不能互换。V100 包使用 CUDA 12.9，因为 CUDA 13 已移除 Volta 离线编译支持。需要兼容对应 CUDA Runtime 的 NVIDIA 驱动，以及 Microsoft Visual C++ 2015–2022 x64 运行库；所需 CUDA 用户态 DLL 已随包提供。

## 快速开始

完整解压到不含中文字符的路径，将匹配的 NInfer v3 `.ninfer` 模型放到包根目录并命名为 `model.ninfer`，或者使用 `-Model` 指定绝对路径。在解压目录运行：

```powershell
nvidia-smi -L
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\start-ninfer.ps1 -Gpu '0'
```

默认服务地址为 `http://127.0.0.1:18200/`，OpenAI 兼容 API 为 `http://127.0.0.1:18200/v1`。默认配方启用 CPU vision、自适应 MTP4 和 ngram31。缺少视觉或 MTP 权重时，请改用公共入口并显式选择配方；设置 `-MtpDrafts 0` 时也不要开启 adaptive MTP 或 ngram。可先运行以下命令检查实际参数，不加载模型：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\start-ninfer.ps1 -Gpu '0' -DryRun

# 无视觉、无 MTP 的基础配方
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows\start-backend.ps1 `
    -Backend ninfer -Model 'D:\models\model.ninfer' -Gpu '0' `
    -Context 32768 -Budget 16384 -Reserve 1024 -HostMiB 4096 `
    -Prefill 128 -MaxTokens 1024 -KvType int8 -MtpDrafts 0
```

## 本轮变化

- 新上游加入 Turing `sm75` 和 Volta `sm70` 构建路线，并更新 Windows/MSVC、CUDA Graph、GDN 和量化转换路径。
- 合并最短剩余 prefill、按轮分配 decode、语法掩码重叠、自动 proposal head、目标分布耦合验证、逻辑采样位置和 Host cache 指标。
- 保留 KVMem 的 64-token Main/MTP 页、GDN checkpoint、B/R/H、LRFU、RAM/SSD 分层、取消恢复、工具调用和推理输出契约。
- 修复主动正常停止会错误锁存故障的问题；HTTP 正常停止现返回退出码 0，真实故障仍保持锁存。

## 已验证与限制

两个 worker 均完成 Release 编译、嵌入架构核对、文件指纹核对、依赖收集和干净 PATH 下的 `--help` 启动检查。功能与真实模型回归在 RTX 5050 Laptop 上完成，包括 ordinary/Graph、会话、工具历史、自适应 MTP/ngram、并发、取消恢复、Main/MTP/GDN 状态字节检查及 HTTP 接口。

本轮没有 RTX 20、TITAN RTX 或 V100 实卡，因此 RC 的主要目的就是收集这些卡的加载、推理和错误信息。没有老卡性能结论，也没有双卡、完整 Gemma 4/Flash-Next、真实视觉或全部历史长上下文矩阵的资格结论。Gemma 4 和 Qwen4Exp 的 KVMem 组合当前会明确拒绝。

FP16 GDN 配合自适应 MTP4 时，窗口边界附近可因 FP16 舍入和并列分布产生不同 greedy token；普通 FP16、固定 MTP4 FP16 和自适应 MTP4 FP32 的独立重放检查通过。此次没有为了匹配旧 token 序列修改数学或缓存算法，默认 FP32 仍是核心资格路径。
