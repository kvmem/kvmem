# RC1 chat-only update

The Windows RTX50 RC1 archive contains the older lightweight chat, whose
attachment input accepts images only. PR #221 added text/code attachments,
last-message edit and regeneration, and browsing history during generation.
These changes can be installed without replacing RC1's launcher or engine.

## Build the overlay

Use a verified release ZIP and a validated lightweight UI build. The publisher
must supply the original release's SHA-256; the tool does not download inputs.

```powershell
python scripts/launcher/chat_update.py `
  --base-archive artifacts/kvmem-v0.19.0-rc1-ninfer-windows-rtx50-sm120a.zip `
  --base-sha256 8e80016585199a0414219db1e0f6c9941c2690cf28729c1c58cc40566d2d0b16 `
  --chat-ui build/share/kvmem/ui `
  --output artifacts/kvmem-rc1-rtx50-chat-update.zip
```

The output contains current chat assets, `console-build.json`, `SHA256SUMS`
and installation instructions. It preserves the base package's controller
hashes, backend list and release metadata, and updates the chat manifest hash.
Unreferenced historical JS/CSS bundles and the independent monitor are excluded.
The result is approximately 2.92 MB for the validated October 28 chat build.
Both inputs remain unchanged; existing output files are rejected.

Each overlay is specific to its named release archive. Build another overlay
from the corresponding base ZIP for another GPU architecture or release;
do not copy the RTX50 package manifests over the RTX20/30/40 packages.
The builder rejects mismatched package checksums, changed chat protocols and
changed `api.ts` source hashes. An unchanged hash is a compatibility guard,
not a substitute for testing the built assets.

Close the original launcher and chat page, back up the chat directory and two
manifests, then extract the overlay beside `START-HERE-CN.bat` with replacement.
Restart the original launcher and refresh the browser with Ctrl+F5. Keep the
same browser and console address for existing browser-local history.

## Validation on October 29, 2026

The base archive's SHA-256 matched the public
[RTX50 RC1 release asset](https://github.com/kvmem/kvmem/releases/tag/v0.19.0-rc1).
The isolated installation retained all 39 original controller files, the
native worker, DLLs and embedded Python. Only chat assets and their manifests
were changed. The original startup check and all package checksums passed.

The original RC1 controller and NInfer worker were exercised through Chromium
with Qwen3.5-4B-MTP-Q4_K_M on an idle RTX 5050 Laptop. The preferred RTX 5060 Ti
was occupied; this was a functional test, with no performance comparison.

- Ordinary streamed reply returned `READY`.
- A UTF-8 TXT attachment containing a code word and count returned `ORANGE`.
- Regeneration reused the same prompt and returned `ORANGE`.
- Editing the question retained the attachment and returned `37`.
- Refresh retained the edited conversation and text attachment.
- A text file larger than 1 MiB was rejected before any inference request.
- All 24 observed JS/CSS responses succeeded; no browser script errors occurred.

Existing `test-chat-actions.cjs` and `test-chat-props.cjs` regressions also
passed against the updated assets. They cover image-only input, drag/drop,
attachment-only prompts, cancellation, edits, history and parameter handling.
The llama.cpp, NInfer and PolyStrata parameter cases use native-contract
fixtures; actual GPU inference in this validation was NInfer only.

The chat protocol remains version 1. `ui/lightweight/api.ts` and
`scripts/console_chat.py` are unchanged from RC1. Text files become ordinary
`messages[].content` strings; the existing console chat route forwards them
to `/v1/chat/completions`. No upload endpoint or new native field is required.

The complete newer console also includes launcher changes and the independent
Windows MIME fix. Those changes are outside this chat-only overlay. Native/CUDA
compilation, model-quality benchmarking and public asset upload were not part
of this validation.

The portable validation record is in
[`v0.19.0-rc1-chat-update-validation.md`](v0.19.0-rc1-chat-update-validation.md).
The repository packager produced the same 70 chat files byte-for-byte as the
2.93 MB integration-test overlay. ZIP metadata, the installation note and
provenance metadata account for the size/hash difference. The resulting package
checksums and unchanged controller hashes were verified again. Seven packaging
tests and eight CI-classification tests passed; no GPU rerun was needed for
identical chat assets.
