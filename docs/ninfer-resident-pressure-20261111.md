# NInfer 驻留 KV 整理与异步等待验证

实现始于 2026-11-11，最终验证完成于 2026-11-12。测试基于主线 `0025b840`，工作分支为 `codex/ninfer-async-resident-pressure`。本报告记录提交前的验证快照，提交及合并状态以仓库记录为准。提交审计核对的后续主线 `2abf28c0` 未改变 NInfer 基线或补丁链。

本次减少了 Layerwise Pressure 整理中的 Host 打包、回传和阻塞等待。频繁刷新的诊断负载收益明显；常用 16k reserve 下，完整任务2和 4/8 路总体变化较小，不能声称通用 decode 提速。前缀未命中策略不在本次范围内。

## 实现范围

- 单 GPU、普通目标或 DFlash2 的驻留页 Pressure 默认直接在 GPU 内整理各层 K/V 和 scale。选集必须是已有驻留页的有序子集，按安全顺序、有限批次搬运，保留原生字节和原选页策略。
- 共享物理页先经过写入保护。搬运期间目标覆盖不发布，请求持有私有复制流、完成事件和已计费元数据；其他就绪请求可以继续运行。完成时验证 stamp、lane epoch、地址和 frontier，再发布全部目标层。
- 取消、异常和过期完成不能发布部分结果；释放页前排空该请求的复制流。控制 token 准备也可以返回等待。部分 prefill 按已完成 token 累计原有服务配额，纯等待不消耗计算配额。
- Host 恢复在原有 pinned 暂存区中使用两个槽位，打包下一批时允许上一批上传。只在槽位复用和返回前等待相应事件，不扩大暂存预算。
- MTP 独立 KV、多 rank、诊断 readback、import/probe 准备保留原恢复路径。本次没有新增 CUDA kernel 或 GPU 影子窗口。

归档新 KV、选页、共享页保护及 CUDA 拷贝提交仍有同步 Host 工作。因此本实现没有消除所有停顿。当前公开非滚动请求会为声明的完整最大输出预留空间，**输出超过 gen reserve 并不自动触发 decode 滚动 Pressure**。本次小 reserve 诊断中的 52 次整理实际发生在 prefill。

## 性能结果

硬件为 RTX PRO 6000 Blackwell 96 GB，Windows；模型为 Unsloth NVFP4 27B + DFlash2 Q3，目标 KV 为 int8。每组性能测试只运行一次，结果不提供统计显著性保证。

### 频繁整理的阶段计时

4 路，每路约 16k 输入、8k 输出，K=12288、G=512，chunk=4096。两版各发生 52 次整理；阶段计时开启，不能与关闭诊断的正式吞吐直接混用。

| 指标 | 原路径 | 新路径 |
|---|---:|---:|
| 平均刷新占用时间 | 74.95 ms | 39.37 ms |
| 平均刷新从开始到完成 | 74.95 ms | 39.58 ms |
| 平均归档 | 8.64 ms | 8.16 ms |
| 平均规划 | 4.09 ms | 6.42 ms |
| 平均 Host 打包 | 47.77 ms | 驻留路径省去此步骤 |
| 平均复制提交 | 1.93 ms | 24.71 ms |
| 平均显式完成等待 | 9.54 ms | 0 ms |
| 文档批次耗时 | 12.78 s | 11.27 s |
| 整体请求耗时 | 62.41 s | 60.67 s |
| 满 4 路 decode | 929.84 token/s | 923.15 token/s |

原路径的打包、提交和等待包含在平均 62.09 ms 的 restore 中，表中各行不能重复相加。新路径约 24.71 ms 的提交本身仍占用 Host；显式等待为零也不表示 GPU 复制没有耗时。新路径额外记录的选页均值为 3.67 ms，位于上述刷新时间之外；原版没有单独记录此阶段。

### 常用参数，4/8 路

K=36864、G=16384、chunk=4096、DFlash draft=5、sessions=16、Host=32768 MiB、decode-rounds-per-prefill=1。每路先发送约 64k 文档并确认，再单独提问；固定输出 8192 或 17408 token，temperature=0、seed=42，关闭阶段计时和反馈 hash。

| 并发 / 每路输出 | 整体时间，原→新 | 满并发 decode，原→新 | 文档有效输入速度，原→新 |
|---|---:|---:|---:|
| 4 / 8192 | 130.22→130.92 s | 671.27→673.37 token/s | 5152.82→5097.83 token/s |
| 8 / 8192 | 288.12→287.79 s | 960.92→955.50 token/s | 4928.05→4948.76 token/s |
| 4 / 17408 | 190.71→190.11 s | 657.36→656.80 token/s | 5008.93→5083.39 token/s |
| 8 / 17408 | 414.36→409.49 s | 907.25→917.22 token/s | 4910.97→4970.68 token/s |

满并发 decode 仅统计原生计数器确认全部槽位处于 decode 的区间，排除冷 prefill 和尾部；文档有效输入速度是输入总量除以整个文档批次时间，并非单 kernel 速度。4 路问题命中模式仍为 `[0,65536,65536,65536]`；8 路仍只有后三路命中，未改变缓存策略。

两版每组全部响应文本 hash、输入/输出量、缓存命中及草稿生成/接受数一致，共核对每版 48 个请求。整体耗时变化约为 -1.18% 至 +0.54%，说明这组常用负载总体接近持平。17408 输出组也不能被当作已经证明 decode 期间发生滚动整理的测试。

### 完整 256k 任务2

沿用历史请求与 0.19 参数约定，G=16384、chunk=4096、单路、thinking=128、每次 max_tokens=512。两版都完成 33 次请求、32 轮工具请求，最终输入 261546 token，总输出 15187 token。逐请求文本、usage、命中、草稿计数及接受数全部一致。

| 全部 33 次请求指标 | 原路径 | 新路径 |
|---|---:|---:|
| 请求总耗时，不含服务启动 | 197.86 s | 196.05 s |
| 原生 prefill 总时间 | 80.09 s | 78.64 s |
| 原生 prefill 加权速度 | 3279.87 token/s | 3340.06 token/s |
| decode 加权速度 | 143.49 token/s | 143.48 token/s |
| decode 排除首 token 的速度 | 143.18 token/s | 143.17 token/s |
| TTFT 中位数 | 2.668 s | 2.664 s |
| 采样峰值显存 | 25660 MiB | 25660 MiB |

本轮总耗时降低约 0.92%，prefill 提升约 1.84%，decode 持平。它是固定历史请求重放，未把本轮模型输出作为后续工具参数反馈，也未新增语义质量评分。

### 混合负载和取消

三路后台生成就绪后，再加入一个 58282 token 的冷输入请求；后台每路强制输出 4096 token，冷请求输出 64 token。使用上述小 reserve 配置及阶段计时。

| 观察值 | 原路径 | 新路径 |
|---|---:|---:|
| 冷请求耗时 | 22.10 s | 18.19 s |
| 冷请求期间总 committed decode 计数增量，含冷请求 | 1360 | 1501 |
| 采样到的最长计数不变区间 | 302 ms | 222 ms |

两版冷请求响应相同，但后台请求在自然结束点后被强制继续生成，三路后续文本均不完全相同。**这组是调度观察，不是同输出严格吞吐对照；不能把全部差异归因于本次改动。** 约 50 ms 轮询也不能证明每次 DMA 与计算的精确重叠。可以确认新路径下其他请求持续推进。

新版本另完成 6 次长 prefill 中的 HTTP 断开，随后 128 token 请求正常完成。HTTP 断开并不保证精确命中复制进行中的时刻；另有原生 fixture 直接销毁未发布事务，验证取消排空、共享检查点不变和地址回收。

## 正确性、构建与复现

最终原生测试 10 项及排障开关测试 3 项全部通过：

- 两种物理页布局、逐层不同选集、连续两次压缩、部分尾页、共享/独占地址；K/V/量化 scale 原字节相等，原共享检查点不变。
- 冷 Host 恢复的 1/2/80 条暂存容量、验证模式、单槽和双槽；过期源、非法选集与不足暂存拒绝。
- 实际 Query/Output、内部滚动 Pressure、prefill pacing/service、真实 27B DFlash2 正向执行、取消、过期完成、控制 token 与检查点。
- `NINFER_RESIDENT_LAYER_PRESSURE=0`、`NINFER_ASYNC_LAYER_PRESSURE=0`、`NINFER_LAYER_RESTORE_PIPELINE=0` 的回退分别通过。

测试中修正了两处既有夹具假设：固定申请 32 MiB 的额度隔离测试需显式配置足够元数据；回收测试需保留真实 checkpoint，而非只有空 history。后者已在基线生产库上复现相同失败。这两处均只修改测试，生产预算与淘汰策略未改变。

生产改动涉及 7 个 Host C++ 编译单元，按需增量编译，**CUDA 编译为 0**。51 个固定后端补丁已从上游基线离线逐步重放，逐项 SHA/tree、最终树及新增补丁正反向应用均通过。准备脚本、CI 分类、可移植验证、公开证据、multi-needle 和 native stats 的相关本地测试通过；Windows 上两项仅适用于其他平台的检查按原规则跳过。

4/8 路吞吐矩阵使用 `0612e9a7…` 二进制；最终修正了控制 token 等待和 detach 防护，任务2、混合及生命周期测试使用最终 `a2432b87…`。没有为这两处边界修正重跑整张吞吐矩阵。

最终后端树为 `372c2415d7a681e9bf17ab95100a62b7bd37725d`。实现位于 [resident-pressure 补丁](../backends/patches/ninfer-resident-pressure.patch)，由 [versions.json](../backends/versions.json) 接入；完整配置、计数、SHA 和资格范围见 [机器可读报告](benchmarks/ninfer-resident-pressure-20261111.json)。原始请求、响应、SSE、日志及可运行脚本保存在 PRO6000 的 `D:/KVMem/logs/ninfer-async-refresh-20261111`。

下一处值得单独测量的是仍约占 25 ms 的 Host 拷贝提交，以及新 KV 的归档。后续若继续压缩这两段，应保持当前原生字节与事务所有权检查，并使用输出一致的混合负载隔离调度收益。
